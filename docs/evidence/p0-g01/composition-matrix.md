# Delta de interfaz y composición

| Capacidad/cruce | Base autorizada | Candidato G01 |
| --- | --- | --- |
| Crear plantilla con varios recursos nominales cantidad 1 | API; sin productor Settings universal | Selector UI reutilizado en Crear/Editar |
| Editar físicos sin cambiar coach | Requisitos reenviados sólo al cambiar coach | Guardado independiente y revisión atómica |
| Coach asignado/específico × físicos explícitos | Mecanismo existente; riesgo de reconstrucción al tocar coach | Entradas separadas, físicas conservadas, sin duplicación |

| Cruce anterior, orden inverso | U02d Stage SQL | Conservado con productor UI |
| Variante AB→AC, ambas ordenaciones | SEARCH_EXHAUSTED, 10.000 ramas | Misma frontera; no se eleva a éxito |
| U00x / U02b aislados | Controles previos con SQL | Controles de regresión, separados de la ganancia UI |

La ganancia es autoría de una dimensión ya consumida: no aumenta el dominio del solver. `PRODUCTIVE_COMPOSED` mantiene el significado y la frontera precisa de U02d. La comparación UI/API exige igualdad literal de requisitos SQL de todas las plantillas de cada día, EngineInput, propuestas, trabajo, certificados, Draft y filas Stage. No usa remapeos por nombre ni elimina campos divergentes.

Los metadatos y demás autoridades del integrado siguen por sus APIs o editores originales; sólo se sustituye el productor de requisitos físicos. El CRUD separado demuestra alta íntegra por UI con dos recursos y edición de coach/concurrencia/permisos. No se presenta este control como autoría íntegra de todas las capacidades de la jornada integrada.

Primera frontera operativa restante conservada: búsqueda AB→AC a presupuesto original. Brechas de interfaz siguientes: `byType`/`anyOf` y las rutas coach, entre otras del roadmap, permanecen abiertas. El corte 28-10-2026 no se modifica retroactivamente.
