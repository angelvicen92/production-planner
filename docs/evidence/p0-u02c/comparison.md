# Comparación con U00w/U00x y U02b

| Baseline | Lo certificado | Relación con esta auditoría |
| --- | --- | --- |
| U00w | Tripletas nativas múltiples y dominio/fijo, Main/Vocal, witness y Stage SQL | Reutiliza geometría, elección común y materialización; no certificaba fases/conjunta/pausa |
| U00x | Anclajes + ámbitos independientes, 19/19 y 20/20, parcial/continuación SQL | Acredita ortogonalidad y coexistencia disjunta; no certificaba la estructura U02b |
| U02b | 24/24, Main/Vocal, dos coaches, fases REQUIRED, unidades fijas, conjunta y pausa | Se conservan sus originales y variante AB→AC; control nuevo hasta SQL |
| U02c antes | Mismas familias existentes, exclusión cruzada observable | Hipótesis de autoría; aún no bastaba para recomendar retirar guards |
| U02c después del diagnóstico | 24+3 representadas por APIs, rechazo auténtico en ambos órdenes, contrafactual físico y consumidores SQL delimitados | No amplía soporte productivo; prepara una unidad funcional end-to-end |

No se atribuye a U02c una regresión por comparar 207 ramas de un modelo con tres tareas nuevas frente a las 127/160 de U02b. Toda conclusión de física usa el mismo EngineInput y presupuesto, con la única intervención de reunir las autoridades excluidas. Los replays fríos comparan decisiones y contadores de idénticos inputs.

El conteo 27 no mide cobertura A2 global. El A2 canónico mantiene 266 obligaciones históricas como regresión. Las tres nuevas de aquí son tareas propias, configurables mediante la App, y requieren anclaje/ámbito para expresar su semántica productiva completa. Sin esas autoridades, almacenar las filas no equivale a representar una operación Reality correctamente.

Los controles reales de esta unidad ejecutan U02b y U00x; el verificador U02b compara un stack nuevo con su archivo histórico, por lo que sus 12 Stages contabilizados contienen **6 nuevos y 6 históricos**. U00x crea **3 Stages nuevos**. No se suman a Stages integrados U02c, que son cero.
