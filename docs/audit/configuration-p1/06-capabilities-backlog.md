# H. Matriz de gaps y backlog de implementación

## Estado del registro frente al código

`shared/configurability.ts` contiene 27 capacidades. Conteos reproducidos: **3 PRODUCTIVE, 15 PARTIAL, 3 MISSING, 5 BLOCKED, 1 NOT_APPLICABLE**. No se modifica el registry durante P1. El informe `PRODUCT-CONFIGURABILITY-AUDIT-v2.4.md` y dos expectativas de `shared/configurability.test.ts` están desactualizados frente a ese registro y Fuentes actuales.

Se distinguen tres ejes: estado declarado en registry, implementación comprobada por capas y certificación pendiente del entorno. La lectura service-role no certifica RLS, policies ni permisos de cada perfil. La futura actualización del registry debe registrar evidencia concreta y conservar PARTIAL si sólo se resuelve una de las capas.

## Hallazgos adicionales de gobierno

**Readiness no es preflight.** `effectiveConfigurationView.ts` construye muchas capacidades con requiredForDay=false y no deriva todas las incompatibilidades de preflight; un resumen READY puede coexistir con categorías UNKNOWN/PARTIAL. Además el adaptador legacy añade siempre `OPTIMIZER_LEGACY_ENGINE_ADAPTER_V1` y la vista marca OPTIMIZATION INCOMPATIBLE ante cualquier compatibilityWarning. Ese indicador no prueba que el día sea imposible para Next. Deben separarse cobertura de producto, provenance, warnings de compatibilidad y viabilidad del scope real.

**Cobertura de roles por ruta.** La ruta real de PATCH de plantillas es `/api/ta/:id`. `apiRequiredRoles('PATCH','/ta/1')` devuelve null, mientras `/task-templates/1` devuelve admin. El middleware autentica, pero null continúa sin gate de rol; el handler de plantilla no añade ensureAdmin. En vocal-coach-rules (PUT) tampoco se localiza un gate adicional. Control-room-settings es un contraejemplo: el mapa grueso devuelve null, pero su handler PATCH sí ejecuta ensureAdmin; no se clasifica como bypass. Esto es un gap de autorización **de usuarios autenticados**, no una afirmación de escritura pública sin login. Service-role del servidor hace que RLS sola no supla ese gate. Se caracteriza offline; no se intenta explotar con peticiones mutantes live y no se cambian permisos en P1.
